# Certifications product and design review

Reviewed 3 October 2026. Scope: `/certifications`, including its hero and certificate collection. This is an expert review informed by published UX guidance, not a recruiter usability study or evidence of a ranking improvement.

## Product objective

Help a recruiter or engineering manager identify Anuj's relevant learning, open the original credential, and connect that learning to delivered work. Course certificates support the portfolio; they do not independently establish professional proficiency or imply accreditation beyond the issuer's actual document.

## Final design

- Shorter hero heading and supporting copy explain the page before the visitor reaches the collection.
- A bespoke text-free 3D illustration depicts study cards, an orbital form and a mobile device. It conveys learning into software work without reproducing an issuer certificate.
- The hero’s right side contains only the artwork. Course details and original issuer links appear in the collection below.
- React and React Native cards lead the unified collection. All seven supporting credentials remain visible in the same grid and existing priority order.
- A concise learning-to-delivery section connects the career chronology to the Projects page.
- Existing brand tokens, system fonts, navbar, footer, buttons, CTA and server-rendered route metadata are retained.

## Generated artwork

Built-in image generation was used via the `imagegen` skill. The source is retained in Codex's generated-image directory. The project asset is `public/certifications/learning-journey-v1.webp`, compressed to 960 × 640 pixels and 26,962 bytes with Sharp. Its URL is versioned; no homepage asset was changed.

Final generation prompt:

> Use case: stylized-concept. Asset type: decorative hero illustration for Anuj Dhanuka's software engineer portfolio Certifications page. Primary request: an elegant premium editorial 3D still life representing learning progressing into web and mobile development. A small stack of off-white rounded study cards with abstract indented horizontal marks (not legible writing), a sculptural translucent violet atom-like orbital loop floating above the cards, and a slim upright mobile-device silhouette with a blank lavender inset screen, arranged as one cohesive object on a low matte plum platform. Style: refined tactile 3D product render, minimalist, sophisticated software portfolio artwork, believable soft shadows, no cartoon mascots. Composition: landscape 3:2, entire object centered, contained with generous breathing room, angled three-quarter view, balanced asymmetry; clear silhouette at small sizes. Background: uniform very dark plum near #130919 blending into a purple/pink portfolio hero, no horizon line. Lighting: soft lavender key light, restrained pink rim light, delicate glow, crisp edges. Palette: deep plum, violet, soft lilac, off-white with small pink accents. No text, no numbers, no logos, no official certificates, no seals, no ribbons, no badges, no signatures, no checkmarks, no watermarks, no tiny UI controls. Do not depict a real issuer document. Output a beautiful production-ready still image.

## Verification limits

Local automated checks and browser inspection verify rendering, links, keyboard behavior and responsive layout. They do not constitute a full WCAG audit, recruiter testing, a PageSpeed benchmark or production field performance measurement. The existing environment restriction affecting the default Turbopack build remains documented in `docs/seo-audit.md`; a webpack production build supplies generated HTML/XML and local browser verification.

Final local verification: formatting, lint, typecheck, all 18 tests and the webpack production build passed. Headless Chrome confirmed the image-only hero, one nine-card grid and retained “See how I put these skills to work” section at 320, 360, 768, 1024, 1440 and 1920px, with loaded artwork, no document overflow and no reported runtime errors. Keyboard focus, menu activation/Escape return and the in-page anchor passed. Sampled supporting-card body/link contrast was 7.56:1/7.10:1 in light mode and 12.05:1/8.70:1 in dark mode; white text against primary-gradient endpoint colors measured at least 4.60:1 at default and 6.04:1 on hover. A 200% text-resizing check retained all nine cards without horizontal document overflow. These are selected checks, not a full accessibility certification.
